Paikutan: Technical Problems

Issue A: Client-Side Rendering of Effects & Sound Effects
- Over-reliance on Network FX Broadcast: In host.js, clash sparks, rings, and sounds are sent over Supabase as distinct net.send('fx', payload) events.
- Supabase Broadcast Rate Limiting: In net.js, Supabase Realtime is capped at eventsPerSecond: 30. During active clashes (sparks + steering + snapshots), Supabase drops burst broadcast packets.
- Missing Local Audio in Multiplayer: On play.js (lines 112-115), hum and hit sounds are guarded with if (solo && snap && state). In live online multiplayer, the phone relies entirely on receiving remote 'fx' messages to play sounds.

Issue B: Mobile Perspective Distortion & Ground Particle Transparency Layering
- The "Underground Particles" Mystery: In scene.js line 125, the circular arena dirt ground (pit) is initialized with transparent: true, opacity: 0.95!
- Three.js Depth Sorting Bug: Because pit is transparent, Three.js sorts it against the transparent particle point clouds (dust and sparks). Looking from a steep angle, Three.js frequently sorts the large ground mesh after the particles, drawing the 95% opaque brown dirt plane over the particles!
- Particle Gravity Sinking: In particles.js, particles have gravity: 4. Once emitted, they fall below y = 0.005 into negative Y-space, sinking physically underneath the ground geometry.
- Extreme FOV Distortion: In scene.js line 531, dynamic FOV is calculated as 2 * atan(tan(...) / a). For portrait mobile where a < 0.5, this formula spikes the FOV straight to the 80° clamp limit, causing severe fisheye distortion where tops look microscopic and edge effects disappear.

Issue C: Multi-Touch Concurrency: Skill Tap Blocked During Joystick Drag
- DOM Event Mismatch: In controller.js line 425: const btn = root.querySelector('[data-act=power]'); btn.onclick = () => send('ability', {}); The skill button is bound to onclick!
- Pointer Capture Blocking: The joystick (line 433) calls pad.setPointerCapture(e.pointerId) on pointerdown.
- Mobile Touch Architecture: In iOS WebKit and Android Chrome, when an active pointer is held down with pointer capture on element A, secondary touches on element B with touch-action: manipulation will fire pointerdown, but the browser's synthetic click event is suppressed or held until all touches release!
- Because Dash (line 426) uses pointerdown, it responds; but Power (using onclick) is completely ignored while dragging!

Issue D: Missing Tagalog Emotes & Quick-Chat Taunts from JMDGG (tromPOW)
- Missing Tagalog Quick Chats: The game lacks the quick-chat system from origin/jm-branch. When ported, it should have four slots using Tagalog lines that current Filipino players actually say: QUICK_CHAT = ["Tara G", "Aray mo", "Lala", "Hehe"].
- Phrase Notes: "Tara G" (let's go; the G is short for "game"). "Aray mo" (ouch, that one's on you) is a meme comeback after landing a hit. "Lala" (it's getting wild / that's crazy) reacts to a big clash. "Hehe" is a cheeky laugh after a lucky knock-out.
- Alternate Pool (for rotation or unlockable taunts): "Ikot pa more!" (spin some more; uses the "pa more" meme pattern as a trumpo pun), "Taympers!" (the street-game timeout call), "Sana all!" (playful envy at a lucky hit), "Charot!" (just kidding, after a taunt), "Basag!" (wrecked; MOBA rally call), "Edi wow!" (sarcastic "good for you"), "Ang angas!" (so cool / so cocky), "GG, pre!" (good game, bro).
- Content Rule: Keep the lines family-friendly. The game is shown on a big screen at a DOST school event, so leave out the profanity common in Pinoy MOBA chat (gago, bobo, amp) even though players use it.
- Controller Buttons: src/controller/main.ts rendered pill buttons (chatButtons()) and dispatched { t: 'chat', i: index }.
- Desktop Hotkeys: Host screen supported keys 1 through 6 for taunting; with four slots this becomes keys 1 through 4.
- Visual & Voice Feedback: Ui.ts spawned floating .bubble popups over character heads for 2.6s, while AudioSystem.ts triggered character barks and browser speech synthesis. Quick-chat text and spoken lines should both be in Tagalog. Browser speech synthesis often has no fil-PH voice (and an English voice mangles Tagalog), so the spoken lines should be pre-recorded barks, with TTS only used when a fil-PH voice is found.
- When Paikutan's battle loop was restructured, this system was simply not ported over.

Issue E: Can't Remove CPUs from Brawl Lobby
- One-Way Addition in UI: In host.js line 145 and index.html, the Brawl lobby provides an #btn-add-cpu button, but no button to remove or kick CPUs.
- Engine Support Exists: In engine.js lines 134-150, engine.leave(id) is fully implemented and handles clearing player slots, recalculating roster order, and resetting points.
- Static Slots List: host.js renders player slots as static text: <li><b>P${i + 1}</b> ${who}</li> without any interactive kick action. Once a CPU is added, the host is trapped and cannot free the seat for real players without refreshing the page.

Issue F: Leave / Back from Match UI (Controller & Host)
- Controller Lock-in: On play.html, once a player enters a room code and taps "Join match", #join-screen is set to hidden = true. There is no "Leave Match" or "Back" button anywhere on the phone.
- Trapped in Lobby / Game: If a player enters the wrong room code, wants to change their nickname, or wants to leave a brawl, their only recourse is to force-close or reload the browser tab.
- Host Mid-Match Trap: On index.html, the host has a "Cancel" button in the lobby, but once a match starts, there is no "Exit to Menu" button until the entire best-of-3 finishes at #end-bar.

Issue G: Mobile Waiting Screen UX: Missing Visual Image Icons for Tutorial Steps
- Dense Wall of Text: In controller.js line 180, howTo() returns a plain numbered list (<ol class="howto">) containing 5 dense paragraphs of text.
- Mobile Readability Fatigue: As captured in user testing, mobile players in party/esports environments do not read numbered text blocks. They need clear visual iconography to instantly grasp mechanics: 1. Pick: Top & character selection icon. 2. Paikot: Circular drawing motion / spiral icon. 3. Bitaw: Phone tilting & flicking forward icon. 4. Laban: Clashing trumpo sparks / dash icon. 5. Brawl / Win: Trophy / ring victory icon.

Issue H: No "Join Match" Button: Players Must Host Just to Get a QR, and Can't Play in Their Own Lobby
- No Join Entry Point: On index.html, #menu-main only offers "Host a match", "Practice vs CPU" and "How to play". There is no "Join match" button and no room-code field, so a player who opens the game cannot join an existing room from the menu.
- Forced Host Detour: The only way to reach a join link is to tap Host a match -> 1v1 / Brawl. hostRoom() in host.js (lines 54-67) creates a new room and renders the play.html?room=XXXX QR code. Players have to make a lobby just to generate a QR they can scan.
- Host Can't Play in Their Own Lobby: The device that makes the lobby turns into the arena screen (start('host')) and never takes a player slot. #slots fills only with phones that scan the QR (or CPUs added with + CPU), so whoever made the lobby has to scan their own QR with a second device or sit out.
